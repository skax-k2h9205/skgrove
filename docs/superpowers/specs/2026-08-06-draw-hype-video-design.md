# 뽑기 긴장 연출 — 춤추는 동물 영상

커피뽑기·조뽑기에서 당첨자가 나오기 전에 춤추는 동물 영상을 띄워 긴장을 만든다.

## 왜

지금 뽑기는 **1.28초**(커피) / **0.86초**(조) 만에 끝난다. 버튼을 누르면 결과가
나와 있어서, 뽑는 것이 아니라 조회하는 것에 가깝다. 여럿이 모니터를 같이 볼 때
"누가 걸리나" 하는 시간이 없다.

3D 무대는 이 간극을 못 메운다. 1.28초 동안 도는 조각은 결과를 꾸미는 장식이지
긴장을 만드는 장치가 아니다.

## 결정 사항

### 1. 타이머를 걷어내고 사람이 끊는다

```
커피 살 사람 뽑기  →  [영상 재생 · 이름이 130ms 마다 바뀜]  →  지금 멈춰!  →  3D 당첨 연출
조 섞기 시작       →  [영상 재생]                          →  지금 멈춰!  →  3D 편성 연출
```

`drawCoffeeBuyer` 의 `setTimeout(…, 1280)` 과 `drawTeams` 의 `setTimeout(…, 860)`
을 없앤다. 결과는 **두 번째 클릭이 정한다.**

한 번 누르면 끝나던 것이 두 번으로 늘어난다. 혼자 조를 짤 때는 손이 한 번 더
가지만, 이 화면의 목적이 "공정하게 배정하기" 가 아니라 "같이 보며 웃기" 라서
그쪽을 택했다.

이름이 깜빡이는 기존 롤링(`coffeeRound` / `coffeeSpotlight`, 130ms 간격)은
**유지한다.** 영상 위 자막에서 이름이 계속 갈아치워지는 것이 "아직 안 정해졌다"
를 나르는 유일한 신호다. 없으면 그냥 동물 영상을 보는 시간이 된다.

### 2. 3D 는 끄지 않고 덮는다

새 컴포넌트가 `.draw-stage` 위에 절대배치로 `<video muted loop playsInline>` 를
덮는다. 멈추면 200ms 에 걷히고 그 밑의 3D 가 드러난다.

**캔버스를 언마운트하지 않는다.** 뽑을 때마다 3D 를 껐다 켜면 WebGL 렌더링
컨텍스트가 쌓이다 브라우저 한도(보통 16개)에 걸려 화면이 통째로 사라진다 —
`drawScene.ts` 서두가 경고하는 함정이 그대로 재현된다.

### 3. 클립은 시작 순간에 뽑아 고정한다

고양이 · 하마 두 개를 두고 **뽑기를 시작하는 순간 랜덤으로 하나**를 골라
`ref` 에 고정한다. 상태에 두면 재렌더마다 다시 뽑혀 재생 중에 동물이 갈아치워진다.

멈추는 시점을 사람이 잡는 이상 같은 영상을 오래 보게 되므로, 회차마다 달라지는
편이 반복 사용에 견딘다.

### 4. 에셋 — `public/hype/{cat,hippo}.webm`

원본은 인스타 릴스 화면 녹화라 상태바 · 하트/댓글 버튼 · 계정명 · 하단 탭이
그대로 찍혀 있고, 각각 6.4MB / 56MB 다. 그대로는 못 쓴다.

브라우저에서 재인코딩한다(이 PC 에 ffmpeg 이 없다). UI 를 잘라내고, 춤이 잘
보이는 3초 구간만, 세로 480px 로 축소 — **각 300KB 이하**가 목표다.
첫 프레임을 `poster` 로 같이 뽑아 로드 전 검은 화면을 막는다.

webm 을 못 읽는 브라우저에서는 **영상을 안 띄운다**(`onError` → 숨김). mp4 를
같이 넣으면 용량이 두 배가 되는데, 영상이 없어도 뽑기는 된다.

### 5. 지켜야 할 것

- **소리 없음(muted).** 사무실이기도 하고, 브라우저 자동재생 정책상 muted 여야
  재생이 시작된다.
- **`prefers-reduced-motion` 이면 영상을 안 띄운다.** `DrawCanvas` 가 3D 에 대해
  이미 하는 판단과 같게 간다.
- 영상은 `aria-hidden`. 상태는 **버튼 라벨이 `지금 멈춰!` 로 바뀌는 것**과
  자막이 나른다.

## 검증

기존 353개 중 뽑기에 기대는 테스트는 없었다. 이 저장소의 테스트는 전부 순수
규칙 모듈에 붙어 있고 컴포넌트 테스트 기반(jsdom · testing-library)이 아예 없다.

**"멈추기 전에는 결과가 없다" 는 테스트로 못 박았다.** 그 한 줄을 위해 컴포넌트
테스트 기반을 새로 들이는 것이 저장소의 테스트 모양을 바꾸는 값에 비해 얻는 게
적었다. 이 규칙은 지금 구조가 대신 보장한다 — 결과를 정하는 코드 경로가
클릭 핸들러 하나뿐이고, 시간이 지나서 결과를 만드는 타이머가 남아 있지 않다.

대신 **테스트가 실제로 잡아 줄 수 있는 것**을 박았다(`hypeClips.test.ts`).
영상 경로는 코드가 문자열로 조립하므로(`/hype/${clip}.webm`) 번들러가 확인해
주지 않는다. 이름이 어긋나면 빌드도 타입검사도 통과하고 화면에서만 조용히
까맣게 나온다. 파일 존재와 용량 상한(300KB)을 검사한다.

### 확인하다 나온 것 — 쌓임 순서 결함

무대를 4:5 로 키우고 밝은 영상을 넣자, 스크롤 시 **뽑기 무대가 고정된 참여자
패널을 덮는 것**이 드러났다. 당첨 조각이 참여자 목록 위에 떠 있는 것처럼 보였다.

원인은 이번 작업이 아니라 원래 있던 구조다. `.participant-panel` 은
`position: sticky`, `.draw-stage` · `.coffee-draw-stage` 는 `position: relative` —
셋 다 `z-index` 가 없었다. z-index 없는 배치 요소끼리는 DOM 순서가 이겨서 뒤에
있는 무대가 위로 올라왔다. 무대가 작고 어두웠을 때는 눈에 안 띄었을 뿐이다.

두 곳을 고쳤다.

- `.participant-panel` 에 `z-index: 1` — 고정해 두는 쪽이 위에 있어야 한다.
- 두 무대에 `isolation: isolate` — 무대 안 자막이 쓰는 `z-index: 1` 이 밖으로
  새어 나가 패널과 직접 겨루던 것을 안에서 끝나게 한다. 이것 없이 패널만
  올리면 자막만 다시 뚫고 올라온다.

측정으로 확인했다: 겹침 220~307px 구간을 24px 간격으로 훑어 최상단 요소가
전부 참여자 패널 쪽인 것을 확인했다(커피뽑기 · 조뽑기 양쪽).

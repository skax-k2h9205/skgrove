# UI/UX 전면 리디자인 설계

작성일: 2026-08-04
대상: skgrove 웹앱 전 화면(13개)
브랜치: `feature/ui-redesign`

## 1. 배경

현재 디자인은 딥그린 셸 + 라임 액센트 + 흰 카드 조합의, 정돈되어 있지만 2022년경 엔터프라이즈 SaaS 문법이다. 실측한 문제는 다음과 같다.

- `src/styles.css` 한 파일에 139KB / 1237개 규칙. 상단에 디자인 토큰이 정의되어 있으나 개별 규칙이 하드코딩 값을 병행 사용한다(예: `--color-shell`이 있는데 `.sidebar`는 `#17352f`를 직접 사용). 전역 색 변경 비용이 토큰 도입 이전과 사실상 같다.
- 브랜드색이 표면(surface)을 점유한다. 사이드바 전체와 히어로 전체가 딥그린이다.
- 한국어 줄바꿈 제어가 없다. `word-break: keep-all` 선언이 0건이며, 로그인 히어로에서 "작게"가 "작 / 게"로 분리되는 현상을 확인했다.
- 반응형 미디어쿼리가 8개뿐이며 화면별로 브레이크포인트가 제각각이다(520 / 720 / 900 / 1100px 혼재).
- 투표 앱임에도 집계 결과가 시각적 주인공이 아니다. 안건 카드에서 "찬성 18 / 반대 5"가 12px 회색 텍스트로 다른 메타데이터와 동등하게 나열된다.
- 안건함이 카드 그리드라 1280px 화면에 3건만 보인다.
- 빈 상태가 스타일 없는 맨 텍스트다.
- `@keyframes` 10개 중 8개가 커피뽑기 화면에 몰려 있고 나머지 화면은 정적이다.
- 다크모드 대응이 전무하다(`prefers-color-scheme` 0건).

## 2. 확정된 결정

| 항목 | 결정 |
|---|---|
| 범위 | 전면 리디자인 (레이아웃·셸 구조 포함, 13개 화면 전부). 내비게이션 항목 구성은 예외로 현행 유지 — 아래 참조 |
| 시각 문법 | 하이브리드 — 업무면은 Linear(고밀도 행) + Polymarket(집계 우선), 문화면은 Notion 한국어판(큰 한글·캐릭터·여백) |
| 팔레트 | C. Moss & Clay (모래빛 베이스 + 이끼 + 점토) |
| 다크모드 | 이번 라운드 제외. 단 토큰은 역할 기반으로 명명해 추후 `:root[data-theme="dark"]` 블록 추가만으로 대응 가능하게 한다 |
| CSS 구조 | `src/styles.css` 한 파일 유지 + 하드코딩 값 전량 토큰 흡수 (토큰 경유율 100%) |

### 내비게이션 항목 구성을 유지하는 이유

"전면 리디자인"에는 통상 정보구조 재편이 포함되지만, `src/navigation.ts`의 항목 구성(13개 항목 / 3개 목적 그룹)은 이번 범위에서 제외한다. 직전 작업에서 평면 13개를 "말하고 정하기 / 함께하기 / 살펴보기·관리"로 묶는 재편이 이미 의도적으로 수행되었고, 그 판단(핵심 흐름이 유머게시판·커피뽑기와 같은 무게로 읽히는 문제)은 지금도 유효하다. 시각 리디자인과 IA 재편을 동시에 진행하면 어느 쪽이 개선/악화를 만들었는지 분리 관측할 수 없다.

사이드바의 **표현**(색·밀도·접힘 동작)은 변경 대상이며, 변경되지 않는 것은 항목의 구성과 그룹핑이다.

이 판단에 이견이 있으면 IA 재편은 별도 라운드로 분리해 진행한다.

### 채택하지 않은 대안과 이유

- **Ink & Lime 팔레트**: 선택된 문법(Linear + Polymarket)과의 적합도와 다크모드 전개가 가장 좋았으나, 문화면이 차가워지는 점 때문에 채택되지 않았다.
- **CSS Modules / Tailwind 도입**: 47개 소스 파일을 전부 건드려야 해 리디자인과 동시 진행 시 회귀 위험이 과도하다.
- **기능별 CSS 파일 분리**: 이름 충돌과 로드 순서를 직접 관리해야 하는 비용 대비 이득이 이번 범위에서 크지 않다.

### 알려진 약점과 완화책

C 팔레트는 두 가지 약점을 갖는다. 설계에서 다음과 같이 완화한다.

1. **업무면이 흐릿해질 수 있음** — 이끼색이 저채도라 위계를 만들기 약하다. 완화책: 업무면의 위계는 색이 아니라 명도와 굵기로 만든다. 퍼센트 등 핵심 숫자는 `--color-ink`(15.5:1) 굵은 글씨로 두고, 이끼색은 상태 점과 진행바 채움에만 사용한다.
2. **웜톤 다크모드 난이도** — 웜 뉴트럴은 어둡게 내리면 채도가 남아 탁한 갈색이 된다. 이번 라운드는 다크 제외이므로 즉시 문제는 아니나, 추후 다크 램프는 단순 반전이 아니라 색상값을 그린 쪽으로 미세 조정한 별도 램프로 떠야 한다. 토큰 명명이 이를 전제한다.

## 3. 토큰 체계

`src/styles.css`의 `:root` 블록을 다음으로 교체한다. 모든 역할색은 세 표면(surface / page / sunken) 전부에서 WCAG AA(4.5:1)를 통과하도록 계산해 선정했다.

```css
:root {
  /* 표면 — 모래빛 3단. 사이드바는 딥그린이 아니라 page로 내려앉는다. */
  --color-page: #f6f4ef;      /* 사이드바 · 앱 배경 */
  --color-surface: #fffdf9;   /* 카드 · 패널 */
  --color-sunken: #efece4;    /* 호버 · 입력 · 진행바 트랙 */

  /* 글자 — 위계는 색이 아니라 명도로 만든다 */
  --color-ink: #1f2420;       /* 15.5:1 — 제목 · 숫자 */
  --color-muted: #5a5f56;     /*  6.5:1 — 메타 · 설명 */

  /* 역할색 */
  --color-moss: #4f7350;      /* 브랜드 · 찬성 · 통과 */
  --color-moss-strong: #3c5a3d;
  --color-clay: #96502f;      /* 문화면 보조 · 강조 */
  --color-danger: #a33a3a;    /* 반대 · 부결 */
  --color-pending: #77642f;   /* 투표중 · 대기 */

  /* 틴트 — 배지 배경과 짝 글자색(8:1 이상) */
  --tint-moss: #e8efe6;    --tint-moss-ink: #2f4a30;
  --tint-clay: #f5e9e1;    --tint-clay-ink: #5c3018;
  --tint-danger: #f6e5e5;  --tint-danger-ink: #6b2020;
  --tint-pending: #f2eddc; --tint-pending-ink: #4a3d15;

  --color-border: #e2ddd1;
  --color-border-strong: #cfc8b8;

  /* 라운드 — 기존에는 8px 단일값이라 배지와 패널이 같은 곡률을 썼다 */
  --radius-sm: 6px;    /* 배지 · 입력 */
  --radius: 10px;      /* 버튼 · 작은 카드 */
  --radius-lg: 14px;   /* 카드 · 패널 */
  --radius-full: 999px;

  /* 그림자 — 떠 있는 것에만. 나머지 분리는 경계선으로 */
  --shadow-float: 0 8px 24px rgba(31, 36, 32, 0.10);

  /* 간격 — 기존 4px 스케일에 보강 */
  --space-1: 4px; --space-2: 8px; --space-3: 12px; --space-4: 16px;
  --space-5: 20px; --space-6: 24px; --space-8: 32px;
  --space-10: 40px; --space-12: 48px;

  /* 밀도 — 업무면 행 높이. 화면 간 공통 상수여야 한다 */
  --row-h: 44px;

  --ease-ui: 150ms ease-out;
  --ease-enter: 280ms cubic-bezier(0.22, 1, 0.36, 1);
}
```

### 계산된 대비값 (참고)

| 전경 | surface `#fffdf9` | page `#f6f4ef` | sunken `#efece4` |
|---|---|---|---|
| ink `#1f2420` | 15.52 | 14.35 | 13.36 |
| muted `#5a5f56` | 6.45 | 5.96 | 5.55 |
| moss `#4f7350` | 5.30 | 4.90 | 4.56 |
| clay `#96502f` | 5.93 | 5.48 | 5.10 |
| danger `#a33a3a` | 6.41 | 5.93 | 5.52 |
| pending `#77642f` | 5.67 | 5.24 | 4.88 |

`--color-pending`은 초기 후보 `#7d6a34`가 sunken 표면에서 4.47:1로 AA에 미달해 `#77642f`로 조정한 값이다.

### 토큰 명명 원칙

토큰 이름은 생김새가 아니라 **역할** 기준으로 짓는다. 기존 `--color-shell`(사이드바·히어로를 뜻함)은 생김새 이름이라 다크모드나 셸 색 변경 시 이름과 의미가 어긋난다. `--color-page` / `--color-sunken`처럼 역할로 명명하면 추후 다크 램프 추가 시 `:root[data-theme="dark"]` 블록 하나만 덧붙이면 되고 1237개 규칙은 손대지 않는다.

## 4. 한국어 타이포그래피 규칙

전역 규칙으로 선언한다.

```css
h1, h2, h3, h4, p, li, button, label, td, th {
  word-break: keep-all;
  overflow-wrap: anywhere;
}
h1, h2, h3 { text-wrap: balance; }
.num, [data-num] { font-variant-numeric: tabular-nums; }
```

`keep-all`만 단독으로 넣으면 긴 URL이나 공백 없는 영문 문자열이 컨테이너를 가로로 뚫는다. `overflow-wrap: anywhere`를 반드시 짝으로 선언한다.

폰트 스택은 현행 유지한다(Pretendard Variable → Pretendard → Noto Sans KR → 시스템). 직전 커밋에서 이미 확정된 사항이다.

타입 스케일:

| 역할 | 크기 / 행간 | 굵기 | 자간 |
|---|---|---|---|
| display (문화면 히어로) | 28px / 1.35 | 600 | -0.02em |
| h1 (페이지 제목) | 22px / 1.35 | 600 | -0.01em |
| h2 (섹션) | 17px / 1.4 | 600 | 0 |
| body | 14px / 1.75 | 400 | 0 |
| meta | 12px / 1.5 | 400 | 0 |
| micro | 11px / 1.4 | 400 | 0 |

## 5. 문법 분리 규칙

화면별로 임의 판단하지 않도록 판정 기준을 고정한다.

| 문법 | 판정 기준 | 해당 화면 |
|---|---|---|
| 업무면 | 목록을 훑고 비교하는 화면 | 안건함/투표, 액션아이템, 리더 관리함, 알림/메시지, 계정 관리, 파트지수/리포트 |
| 문화면 | 하나를 읽거나 쓰는 화면 | 대나무숲 접수, 팀 추억, 유~머게시판, 동료 성향, 커피뽑기/조뽑기 |
| 혼합 | 상단은 문화면, 하단은 업무면 | 홈, 캔미팅/티미팅 |

**업무면 문법**: 카드 대신 `--row-h`(44px) 고정 높이 행. 그림자 없이 경계선으로 분리. 상태는 7px 색점. 집계 퍼센트는 `--color-ink` 600 굵기로 우측 정렬 + `tabular-nums`. 진행바는 64px 폭 4px 높이.

**문화면 문법**: 28px 한글 디스플레이. 캐릭터 아바타(틴트 배경 + 이니셜, 겹침 배치). 여백 우선(카드 패딩 26px/22px). 핵심 어절에 틴트 하이라이트.

## 6. 컴포넌트 변경 목록

1. **안건 카드 → 행** (`src/features/agenda/AgendaBoard.tsx`) — 퍼센트를 ink 굵은 숫자로 승격. 이끼색은 상태 점과 진행바 채움에만. 1280px에서 3건 → 12건 표시.
2. **사이드바 셸 반전** (`src/components/AppShell.tsx` + CSS) — 딥그린 `#17352f` → `--color-page` + 우측 경계선.
3. **홈 히어로 축소** (`src/features/dashboard/Dashboard.tsx`) — 현재 히어로가 세로 약 350px를 점유해 지표 카드가 접힘 아래로 밀린다. 문화면 문법으로 재작성하되 높이를 줄여 지표를 첫 화면에 올린다.
4. **빈 상태 컴포넌트 신설** — 현재 "지금 투표 중인 안건이 없어요" 등이 맨 텍스트다. 아이콘 + 설명 + 다음 행동 버튼 구조로 통일하고 전 화면에 적용한다.
5. **배지/칩 통일** — 통과·부결·투표중·대기가 화면마다 다른 스타일이다. 4개 틴트 짝(`--tint-*` / `--tint-*-ink`)으로 단일화.
6. **버튼 계층 정리** — primary(moss 채움) / secondary(sunken 채움) / ghost(투명) 3단.
7. **반응형 보강** — 브레이크포인트를 720px / 1100px 두 개로 통일하고 전 화면에 일관 적용. 사이드바는 1100px 이하에서 접힘.

## 7. 실행 순서

회귀 위험이 낮은 것부터 배치한다.

| 단계 | 내용 | 기대 화면 변화 |
|---|---|---|
| 1 | 토큰 정의 + 하드코딩 값 전량 흡수 | 거의 없음 (있으면 그 자체가 발견) |
| 2 | 한국어 타이포 규칙 전역 적용 | 제목 줄바꿈 정상화 |
| 3 | 셸(사이드바·헤더) 반전 | 큼 |
| 4 | 업무면 6개 화면 행 전환 | 큼 |
| 5 | 문화면 5개 화면 재작성 | 큼 |
| 6 | 혼합 2개 화면 + 반응형 정리 | 중간 |
| 7 | 검증 | — |

1단계를 독립 단계로 분리하는 이유: 토큰 흡수만 했을 때 화면은 그대로여야 정상이다. 달라 보이는 지점이 있다면 그 값이 원래 의도와 어긋나 있었다는 발견이다. 색과 구조를 동시에 바꾸면 이 신호를 관측할 수 없다.

4단계가 가장 위험하다. 카드는 세로로 흐르므로 내용이 길어도 늘어나지만, 행은 `--row-h` 고정이라 긴 한글 제목이 반드시 잘린다. 모든 행에 `text-overflow: ellipsis` + `title` 속성(전체 텍스트 보존)을 함께 적용한다.

## 8. 검증 기준

각 단계 종료 시 다음을 모두 만족해야 다음 단계로 넘어간다.

- `npm run build` 성공 (tsc 타입 체크 포함)
- `npm test` 통과 (현재 테스트 파일 8개)
- 13개 화면 전부를 브라우저로 순회 캡처해 육안 확인 — 텍스트 잘림, 대비 부족, 가로 넘침, 겹침 없음
- 720px / 1100px / 1440px 세 폭에서 레이아웃 붕괴 없음
- `styles.css`에 새로 추가된 하드코딩 색상값 0건 (토큰 경유율 유지)

UI 변경은 단위 테스트가 잡아주지 못하는 영역이 대부분이므로, 순회 캡처가 사실상 유일한 증거다. 캡처 없이 완료로 보고하지 않는다.
